# هستهٔ بومی · نسخهٔ آزمایشی ۲

این بخش با بررسی فایل ورودی و پیاده‌سازی مستقل ساخته شده است. ظاهر و کد مدیریتی فایل ورودی وارد پروژه نشده‌اند. پنل افرودیت همچنان پنج‌زبانه است.

## راه‌اندازی

۱. از D1 و تنظیمات فعلی پشتیبان بگیرید. migrationهای `0004` و `0005` افزایشی‌اند و جداول قبلی را حذف نمی‌کنند.

۲. برای مسیر پیش‌فرض، `main = "src/index.ts"` و `NATIVE_ENABLED = "true"` تنظیم می‌شود. این ورودی از Relayهای تأییدشدهٔ `TUNNEL_ROUTES_JSON` استفاده می‌کند. UUID حساب سرویس Relay را فقط به‌عنوان Secret با نام `NATIVE_RELAY_UUID` قرار دهید؛ در Git یا متغیر عمومی ننویسید.

۳. حساب سرویس Relay باید فقط برای عبور ترافیک این هسته باشد. حسابداری کاربران در D1 افرودیت انجام می‌شود. مسیرهای کشور فقط وقتی تولید می‌شوند که Relay آن کشور واقعاً در تنظیمات موجود باشد. وجود یک IP Cloudflare، خروجی کشور مستقل ایجاد نمی‌کند.

۴. برای ورودی مستقیم سوکت، فایل `src/direct-worker.ts` آماده شده است. این ورودی به API `cloudflare:sockets` نیاز دارد. اتصال HTTPS به پراکسی بالادست نیز به همین ورودی مستقیم نیاز دارد؛ ورودی Relay ترافیک آن را بدون TLS عبور نمی‌دهد.

۵. Durable Object اختیاری است. سرویس آن با الگوی `wrangler.state.toml.example` جدا نصب و سپس با `ACCOUNT_STATE` متصل می‌شود. Pages برای این حالت باید به سرویس Worker جدا متصل شود. مسیر پیش‌فرض D1 به این سرویس اضافه نیاز ندارد.

۶. توکن مدیریت و اطلاعات Relay را با `wrangler secret put` تنظیم کنید. برای آمار اختیاری، `CF_ACCOUNT_ID` و Secret برابر `CF_ANALYTICS_TOKEN` لازم‌اند.

## قرارداد حسابداری

حجم رزروشده در سقف مصرف منظور می‌شود تا اجرای هم‌زمان چند Worker سهمیه را رد نکند. حداکثر رزرو D1 برای هر اتصال ۲ MiB است. ماندهٔ رزرو در پایان عادی اتصال برمی‌گردد. در صورت قطع ناگهانی اجرای Worker ممکن است ماندهٔ همان بلوک حساب‌شده باقی بماند؛ این خطا به نفع جلوگیری از عبور از سقف است. وضعیت API عمداً با نام «حجم حساب‌شده / رزروشده» نمایش داده می‌شود، نه مصرف دقیق لحظه‌ای.

قفل اتصال ۹۰ ثانیه اعتبار دارد و هر ۳۰ ثانیه تمدید می‌شود. تغییر سیاست یا UUID حداکثر در تمدید بعدی یا رزرو بعدی اعمال می‌شود. فیلتر DNS، Fragment و کارکرد روی ISPها باید با کلاینت واقعی آزمایش شوند.

## وضعیت انتشار این نسخه

در این اجرا، نسخه‌های آزمایشی Cloudflare خطای اجرای 1101 داشتند؛ حتی نمونه‌های بسیار کوچک نیز هنگام افزودن قابلیت‌های runtime خطا دادند. علت قطعی هنوز تعیین نشده و تشخیص اولیهٔ وابستگی به DO تأیید نهایی نیست. نسخهٔ پایدار ۱.۵.۱ عمداً با این هسته جایگزین نشد. افزودن کد به پروژه به معنای تأیید فعال شدن همهٔ قابلیت‌ها روی حساب فعلی نیست.

مراجع محدودیت‌های پلتفرم: [TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) و [Pages bindings](https://developers.cloudflare.com/pages/functions/bindings/).
